## 完成内容

### 1. 零依赖 Markdown 渲染器
**文件**：`src/utils/markdown.ts`（新增，约 5.3 KB）

为什么不用 marked + DOMPurify：助手回复结构简单（标题、列表、行内代码、加粗），
引两个库会明显增加包体；自己写可先转义再渲染，从根上避免 XSS。

- `escapeHtml()`：统一转义 `& < > " '`
- `safeUrl()`：链接协议白名单，只放行 `http/https/mailto` 与站内相对路径，
  阻断 `javascript:`；裸域名自动补 `https://`
- `renderMarkdown()`：块级解析，支持
  - 围栏代码块 ``` ```（保留语言标记为 class）
  - 标题 `#1–6`、水平线、引用 `>`
  - 无序列表 `- * +`、有序列表 `1.`
  - 段落（连续非空行合并）
- 行内：行内代码 → 链接 → 加粗 → 斜体 → 删除线
  - **顺序很关键**：行内代码先用占位符摘出，避免代码里的 `*` `_` 被当成强调符号
- `toPlainText()`：去格式的纯文本摘要（列表预览等场景）

### 2. 流式回复模块
**文件**：`src/api/stream.ts`（新增，约 3.2 KB）

统一封装「助手回复的流式获取」，两种模式共用同一套 `onDelta` 回调：

- 真实模式：调用已有的 `chatStream(messages, onDelta, signal)`（Day8 就写好的 Fetch + ReadableStream SSE 实现）
- Mock 模式：`buildMockReply()` 依据当前图表配置生成一段 Markdown 说明
  （标题、要点列表、下一步建议、引用提示），`chunkify()` 按 3 字符切块
  + `sleep(18ms)` 逐块吐出，模拟真实吐字节奏
- `sleep()` 完整支持 `AbortSignal`：监听 `abort` 立即清定时器并抛 `AbortError`，
  保证中断是即时生效而不是等下一块

### 4. 状态层接入流式
**文件**：`src/stores/ai.ts`

- `runPrompt()` 里图表校验通过后，不再直接塞一句固定文案，改为调用 `streamExplain()`
- `streamExplain(session, prompt, chart)`：
  1. 先插入一条 `content: ''`、`streaming: true` 的 assistant 消息
  2. 调 `streamAssistantReply`，回调里 `target.content += delta` 并刷新 `updatedAt`

- 注意：直接改 `target.content`（而非替换数组）是为了让 Vue 原地更新，避免每块都重建列表

## 技术要点
- **先转义再渲染**：Markdown → HTML 的每个文本片段都先 `escapeHtml`，再套标签，
  这是自制渲染器最容易漏、也最致命的一步
- **行内代码占位符**：`\u0000CODE${i}\u0000` 先摘出再还原，避免强调符号误伤代码内容
- **原地追加而非重建**：流式场景下高频更新，改 `target.content` 比每次 `map` 重建数组开销小得多
- **中断是一等公民**：`AbortSignal` 从视图 → store → 请求层一路贯通，且 `sleep` 也响应中断，
  否则 Mock 模式点了「停止」还要等几百毫秒才停
- **Mock 与真实同构**：两种模式都是 `(prompt, chart, onDelta, signal)` 签名，
  上层代码完全不需要关心当前走哪条路

## 遇到的问题
1. **`series[0]?.data?.length` 编译报错**：`ChartConfig.series` 元素是数字或数字数组，
   没有 `.data` 字段。改为 `Array.isArray(first) ? first.length : chart?.data?.length ?? ...`
2. **类型名写成 `ChartSession`**：实际定义是 `ChatSession`，`vue-tsc` 报 TS2724。改正即可
3. **流式时滚动不跟随**：原来只监听 `messages.length`，内容增长不触发。
   加入内容拼接后的 watch 源解决
4. **v-html 样式不生效**：scoped 样式默认不作用于动态插入的 DOM，必须用 `:deep()`
