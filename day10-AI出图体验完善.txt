### 2. 会话工具层（纯函数 + 轻量持久化）
**文件**：`src/utils/chatSession.ts`（新增，约 4.7 KB）

设计原则：**不依赖 Vue / Pinia**，全部纯函数，便于测试与复用；持久化只做最薄一层。

- 创建与命名
  - `createSession` / `createId`：id 用「时间戳 + 自增」，避免同毫秒创建冲突
  - `deriveTitle`：由首条提问推导标题（压缩空白、超长截断到 16 字）
  - `isDefaultTitle` / `normalizeTitle`：判断是否仍是默认标题、重命名归一化（空白回落默认、超长截断）
- 消息
  - `appendMessage`：追加消息并补时间戳、刷新 `updatedAt`
  - `recentMessages`：取最近 N 条（供多轮上下文）
- 排序与裁剪
  - `sortSessions`：按 `updatedAt` 倒序
  - `trimSessions`：超过 `MAX_SESSIONS = 20` 时丢弃最旧
- 持久化
  - `parseSessions`：对 `localStorage` 这种不可信来源**逐字段校验**，非法项直接丢弃
  - `loadSessions` / `saveSessions` / `clearStorage`：全部 try/catch，隐私模式或超配额时静默降级为「仅内存」

### 3. 状态层升级为多会话
**文件**：`src/stores/ai.ts`（重写，约 9.9 KB）

- 数据结构：`sessions: ChatSession[]` + `activeId`，替代原来的单条 `messages` 数组
- 派生状态：`activeSession / messages / chartConfig / usedFallback / hasChart` 全部由 `computed` 派生，
  视图层不需要关心「当前会话从哪来」
- 会话操作：
  - `newSession` / `switchSession` / `renameSession` / `clearMessages` / `deleteSession`
  - `deleteSession` 删空后自动 `newSession()`，避免界面出现空壳
  - 首条提问时若标题仍是默认值，自动用提问内容命名（`isDefaultTitle` 判断，不覆盖用户手改的名字）
- 出图流程抽出 `runPrompt(content, appendUser)`：
  - `send()` 追加用户消息后出图
  - `retry()` 复用最后一条用户提问，`appendUser = false`，**不重复追加**用户消息
- 错误分类 `describeError(e)`：把底层异常翻译成「用户看得懂 + 知道该不该重试」
  | 原始信息 | 用户提示 | 可重试 |
  |---|---|---|
  | 401 / 403 / invalid key | API Key 无效或权限不足，请检查 .env.local | 否 |
  | 429 / rate limit | 请求过于频繁（限流），稍后再试 | 是 |
  | timeout / aborted | 请求超时，网络或模型响应较慢 | 是 |
  | network / failed to fetch | 网络异常，无法连接模型服务 | 是 |
  | 5xx | 模型服务异常，请稍后重试 | 是 |
  | 配置不合法 / JSON | 模型返回的图表配置不合法，已切换为默认图表 | 是 |
  - 结果写入 `error` + `canRetry`，决定界面是否展示「重试」按钮
- 保留 Day9 能力：`refine()` / `changeType()` 仍走本地 `chartOps` 即时生效，并追加一条微调说明消息
- 自动落盘：`watch(sessions, ..., { deep: true })`，标题 / 消息 / 图表任一变化即保存

## 技术要点
- **会话即上下文**：把「对话 + 图表」聚合成 `ChatSession`，切换会话就是切换上下文，为后续多轮微调划出干净边界
- **纯函数 + 薄持久化**：会话运算全在 `chatSession.ts`，`localStorage` 只做最薄一层，读写全 try/catch
- **脏数据不进 store**：`parseSessions` 逐字段校验，localStorage 被手动改写或版本变更也不会污染内存状态
- **错误可操作化**：不只显示原始报错，而是分类 → 人话提示 → 是否可重试 → 对应按钮
- **重试不污染历史**：`retry` 复用最后一条用户消息，避免对话被「重试」重复记录
- **并发保护**：`loading` 期间 `send` / `retry` 直接返回，防止连点重复请求

2. **删到最后一个会话后界面空壳**：`deleteSession` 在列表为空时自动 `newSession()` 兜底。
3. **「重试」会重复追加用户消息**：抽出 `runPrompt(content, appendUser)`，重试路径 `appendUser = false`。
4. **点重命名输入框会切换会话**：冒泡到 `li` 的 click，加 `@click.stop` 阻断。
5. **深度监听整个 sessions 的性能顾虑**：会话数量有上限（20）且结构扁平，实测无压力。
6. **本地挂载盘 I/O 异常**：`/mnt/local` 下批量 `cp` / `node` / `git commit` 频繁报 EIO（对象库读取失败），
   改为从 GitHub 克隆干净仓库到沙箱工作区开发，依赖装在工作区内，绕过挂载盘限制。
